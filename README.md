# PAPERCHASERS — UNIT ECONOMICS

Внутренний калькулятор производства и продаж одежды. React + TypeScript + Vite.
Расчёты и сохранение выполняются в браузере, без сервера данных и авторизации.

## Запуск на Windows

Требуется Node.js 22.12+ (или установленный здесь Node.js 24) и npm.
В терминале в папке приложения:

```text
npm ci
npm run dev
```

Если зависимости уже установлены, достаточно `npm run dev`.
Откройте адрес `Local`, напечатанный в терминале. Для остановки — Ctrl+C.
Проверки: `npm test` и `npm run build`. Готовый сайт создаётся в папке `dist`.

## Открыть на телефоне или компьютере в одной сети

1. Подключите устройства к одной доверенной домашней/рабочей сети Wi-Fi.
2. В папке приложения выполните `npm run share:lan`.
3. После сборки терминал покажет `Local` и один или несколько адресов `Network`.
   Откройте на телефоне именно адрес `Network` вашей Wi-Fi/Ethernet сети с портом 4173.
   `localhost` на телефоне означает сам телефон, а не этот компьютер.
4. При запросе брандмауэра Windows разрешайте Node.js только в частной сети.
   Не выключайте брандмауэр целиком. В публичной сети этот режим не используйте.
5. Компьютер должен оставаться включённым, без сна, а терминал — работать.
   Остановка: Ctrl+C. После обновления исходников остановите и запустите команду снова.

Команда открывает временный просмотр собранного сайта на сетевых интерфейсах компьютера.
У него нет входа или шифрования. Используйте только в доверенной сети.
Если порт 4173 занят, команда завершится ошибкой, а не выберет другой порт.
Остановите предыдущий просмотр перед повторным запуском.
Гостевая Wi-Fi сеть, изоляция клиентов, VPN и настройки Windows могут блокировать связь.
Если адресов несколько, выбирайте адрес реального сетевого адаптера, не VPN.
Подключение реального телефона и настройки брандмауэра требуют проверки на ваших устройствах.

**Не перенаправляйте порт на роутере и не публикуйте сервер Vite в открытом интернете.**
`vite preview` предназначен только для временной проверки, а не постоянного хостинга.

## Постоянная ссылка через интернет — рекомендуемый следующий шаг

Разместите содержимое `dist` на статическом хостинге с HTTPS, например Cloudflare Pages
или Netlify. Компьютер после этого не обязан работать. Публикация в этом проекте
ещё не выполнена: аккаунт, адрес и защита доступа не выбраны.

Для ручной публикации на хостинге с загрузкой готовой папки:

1. Перед сменой адреса скачайте JSON всех проектов в текущем браузере.
2. Выполните `npm test`, затем `npm run build`.
3. В панели выбранного хостинга создайте сайт и загрузите **содержимое `dist`**
   (или саму папку/её архив, если этого требует панель). Не загружайте всю папку проекта,
   `node_modules`, JSON с расчётами, личные файлы или секреты.
4. Для автоматической сборки из закрытого репозитория: команда `npm run build`,
   каталог публикации `dist`. Подключение репозитория и публикация — отдельное действие владельца.
5. Если приложение должно быть доступно только вам двоим, сначала настройте
   ограничение доступа средствами хостинга/шлюза. Скрытая ссылка не является защитой.
6. Откройте HTTPS-ссылку на компьютере и телефоне, проверьте создание проекта,
   сохранение после перезагрузки и JSON-перенос. Напарнику передавайте эту же постоянную ссылку.
7. На новом адресе восстановите данные через «Экспорт» → «Загрузить JSON» → «Добавить проекты».
   Для обновления сайта пересоберите и загрузите новую папку `dist` в тот же сайт.

Приложение использует hash-навигацию, поэтому отдельные правила перенаправления страниц
для текущих разделов не нужны. Внешние сервисы и платные тарифы не подключены.
Документация Vite: https://vite.dev/guide/static-deploy.html

## Одна ссылка ≠ общие данные

Проекты находятся в `localStorage` **конкретного браузера и адреса сайта**.
Разные устройства, профили браузера и адреса (localhost, сетевой IP, HTTPS-домен,
а также разные порты) имеют независимые данные. Новый адрес может выглядеть пустым:
это не означает, что проекты на старом адресе исчезли.

- В «Экспорт» скачайте **JSON всех проектов**, передайте напарнику безопасным способом.
- На другом устройстве: «Экспорт» → «Загрузить JSON» → «Добавить проекты».
- Это снимок, а не синхронизация. Повторный импорт создаёт копии, не обновляет старые проекты.
- «Заменить всё» удаляет текущий список. Сначала сделайте резервную копию получателя.
- JSON включает все проекты, в том числе архив, заметки и финансовые данные; файл не зашифрован.
- CSV и PDF предназначены для чтения, не для восстановления редактируемых расчётов.
- Не редактируйте параллельно один набор данных в нескольких вкладках: защиты от конфликтов пока нет.
- Регулярно сохраняйте JSON вне браузера, особенно перед очисткой данных сайта или сменой адреса.

Для редких передач достаточно одной основной версии у ответственного редактора и JSON-копий.
Для **общей актуальной базы** нужен отдельный этап: вход по приглашению для двух участников,
серверная база, права на проекты, версии записей и обработка конфликтов, резервные копии.
Простая публикация, одна Wi-Fi сеть или хранение исходников в OneDrive этого не заменяют.

## Читаемость

`src/readability.css` увеличивает экранные подписи и контраст, задаёт кнопкам высоту от 44 px,
полям — текст 16 px, и адаптирует плотные блоки под телефон. Исходный фирменный стиль
и отдельные правила печатного отчёта сохранены. Окно «Доступ» объясняет перенос данных.
